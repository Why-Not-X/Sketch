# Touch Whiteboard: build status

Spec: `~/Downloads/Touch Whiteboard v1 Build Spec for Claude Code.md`

## M0 Scaffold: done in the Simulator, not yet on a device

- Universal app (`TouchWhiteboard.xcodeproj`, iOS/iPadOS 17+, placeholder bundle ID `com.placeholder.TouchWhiteboard`).
- Swift Package `Engine/` with modules `GestureEngine`, `InkModel`, `ResponseMapping`. No UIKit or Metal in any of them.
- Full-screen `CAMetalLayer` canvas cleared to near-black. Display link set to 120 Hz preferred (60 to 120 Hz range). `CADisableMinimumFrameDurationOnPhone = YES`.
- **Ran:** iPhone 17 Pro and iPad Pro 13" simulators, portrait. **Not checked:** landscape, because the Simulator wasn't rotated, and any real device.

## M1 Latency spike: built, real-device measurement still pending (stop point)

Built:
- Raw touch capture (`touchesBegan/Moved/Ended/Cancelled`, no gesture recognizers), coalesced and predicted touches. Predicted points are dropped when real ones arrive.
- Bounded, pre-allocated event queue with no locks: touches and frames both run on the main run loop.
- G7 ink: glow, tapered ends, width thins with speed, trailing head sparkle. Pencil width comes from force and tilt. Palm rejection for large contacts and fingers while the Pencil is down.
- Ink stored as data in resolution-independent canvas units, so it survives rotation and resizing.
- Pipelines warmed at launch with an off-screen draw.
- `CAMetalDisplayLink` with `preferredFrameLatency = 1`.
- Latency: an `os_signpost` interval `TouchToPresent` (Points of Interest, subsystem `TouchWhiteboard`) from `UITouch.timestamp` to `addPresentedHandler`. A debug HUD shows p50/p95 for touch-down to screen and move to screen, plus the measured Hz. It's also logged every 5 s.

Ran:
- 19 engine unit tests pass (`cd Engine && swift test`).
- Simulator (iPhone 17 Pro, iPad Pro 13"): synthetic strokes replayed through the real input path render correctly (launch argument `-demoStrokes`, debug builds only).
- Device build compiles (unsigned).

**Not measured:** latency on any device. The Simulator has no presented-time API, and its frame rate (around 44 to 50 Hz) means nothing, so the HUD labels Simulator numbers as approximate. Real numbers need a ProMotion iPhone, a 60 Hz iPhone and an iPad.

## M2 Engine and taps: done in unit tests and the Simulator, not yet on a device

Built:
- **Gesture engine** (`Engine/Sources/GestureEngine`): one recognizer per gesture (G1 to G7, G31) and an arbiter that runs them in R2 priority order with shared per-touch state. No allocation per event. All thresholds live in `GestureConfig`.
- **Progressive reveal (R1):** G1 begins on every finger touch-down. A second quick tap adds G2 on top of G1, and a third adds G3. A gesture is confirmed on lift or cancelled the moment the touch stops qualifying (it moves 10 pt or more, is held longer than 250 ms, or a second finger lands).
- **G4 rhythm:** 4 or more taps whose intervals are all within 20% of their mean. It fires on each qualifying tap and moves the pulse there.
- **G5/G6:** G5 starts from the frame tick at 400 ms and grows continuously. Lifting fires G6, with strength capped at 2 s.
- **G7:** now decided by the engine. Ink points are still recorded from touch-down, so the first 10 pt aren't lost while the touch is classified.
- **ResponseSet:** `BaseResponseSet.json` holds all 32 gestures (Appendix A text, haptics and persistence) plus effect recipes for the M2 gestures. It's generated by `Engine/Tools/make_base_response_set.py`. The mapper turns GestureEvents into spawn, update and release commands. Persistence uses one shared `Lifetime` rule.
- **Renderer:** instanced rings, discs and dots, plus GPU particles (analytic motion, one shared buffer of 3,000, oldest overwritten first).

Ran:
- 55 unit tests pass. Every M2 gesture has positive and near-miss traces (for example, a tap that moves 12 pt doesn't count), plus priority tests (a second finger cancels a tap or hold) and mapper tests (keys, replace, release, no-haptics boost, swapping the set changes the reaction). Traces round-trip through JSON.
- iPhone 17 Pro and iPad Pro 13" simulators: a scripted demo (`-demo` launch argument) fires G1, G2, G3, G5→G6, G4 and a fast stroke (G7 + G31) through the real input path. Screenshots confirm each effect and the HUD gesture log.

**Not verified:** anything on a real device (spec acceptance says "on device"), haptics (the mapper emits commands, but the Core Haptics layer is M6 and nothing plays yet), and feel or tuning of any effect.

Decisions taken (please check):
- **G31 after strokes:** a stroke's lift also blooms G31, since "no other gesture claims it" and Appendix A mentions trails on fast lifts. Only confirmed taps and G6 claim the lift. G8 (flick) will claim fast stroke lifts in M3.
- **G3 distance:** taps must be within 30 pt, the same as G2. The spec gives no distance for G3.
- **Slowest rhythm:** G4 counts tempos down to 1.5 s between taps.
- **Rhythm tap that turns into a stroke:** the stroke's touch-down can count as a rhythm tap. If it then turns into a stroke, G4 is cancelled and the pulse fades.
- **Hold then move:** after a G5 hold, moving cancels it and draws nothing. M3 turns this into G14 (hold-drag).
- **Two-finger strokes:** a second finger cancels taps and holds, but each finger can still draw. M4 replaces this with G16 to G26.

## M3 Single-finger depth: done in unit tests and the Simulator, not yet on a device

Built:
- **Mid-stroke upgrades (R1):**
  - G9 scribble: 3 or more reversals within 1 s inside 120 pt. It cancels G7, then erases ink under the finger, splitting strokes, with dissolve particles drifting up.
  - G15 dwell: a pause of 300 ms or more mid-stroke grows an ink blot, which is saved with the stroke.
- **After-the-fact shapes (R3), classified at lift with the first match winning:**
  - G10 circle: snaps into a clean ring kept as ink, plus 3 echo rings 150 ms apart.
  - G11 spiral: an inward spiral pulls particles into a vortex that ends in a flash; an outward one swirls particles away.
  - G12 zigzag: the stroke turns into a flickering, branching electric arc with sparks.
  - G8 flick: a short, fast stroke lifted while moving becomes a comet that slows with drag and bounces off the screen edges.
- **G13 slingshot:** tap, then a quick second touch near it and drag. An elastic line runs from the anchor to the finger; on release it snaps back and launches particles toward the anchor. Draws no ink.
- **G14 hold-drag:** a G5 hold that starts moving. The orb follows the finger and leaves a light trail.
- **Undo history** (`InkHistory`, 64 steps): every ink change is one step. A scribble erase is one undo. A stroke consumed by G8 or G12 never becomes ink, but one undo brings it back (R3). There's no Undo button until M7, so for now **shake the device to undo** (debug builds; in the Simulator, Device → Shake).

Ran:
- 89 unit tests pass. Every gesture G8 to G15 has positive and near-miss traces, for example:
  - a flick versus a long stroke that ends fast
  - a scribble versus a wide back-and-forth
  - a circle versus a half circle and a squashed loop
  - spirals with 1 turn versus 2.2 turns, inward and outward
  - a zigzag versus a gentle wave
  - a slingshot versus a late second touch
  - a hold-drag versus a plain drag
  - a dwell of 0.6 s versus 0.2 s

  Pencil strokes never upgrade (R6). There are also tests for erase splitting, a whole scribble undoing in one step, a consumed stroke coming back, and the undo depth cap.
- Simulator, iPhone 17 Pro, scripted demo (`-demo3`): every M3 gesture fired and rendered (screenshots checked). Three shakes undid, in order, the dwell stroke, then the flick, then the zigzag.

**Not verified:** anything on a real device or with a real finger; the feel and thresholds of the shape gestures (all assumed); and the edge-bounce Tick haptic, which waits for the haptics layer in M6.

Gaps and decisions (please check):
- **Not built yet:** "nearby ink is tugged" (G14) and "nearby ink is pulled into the vortex" (G11). Both need the ink-distortion shader planned for G19, G20 and G27. Pulling existing particles is also not possible yet, because particles move on fixed GPU paths.
- **Strokes that turn into an effect:** the stroke itself flies off (G8) or becomes the arc (G12), and doesn't stay as ink. Undo brings it back.
- **Spiral strokes:** the spiral stroke itself stays as ink.
- **Flick:** needs at least 800 pt/s at lift, a stroke of 350 ms or less, and at least 25 pt of travel, so a long drawing that ends with a fast flourish stays ink.
- **Zigzag:** needs 3 or more corners sharper than about 75°, over at least 60 pt. The first threshold of 100° missed natural hand-drawn zigzags.
- **Blots:** in one Simulator run, the dwell stroke left two blots (the second one small). The unit trace gives one. It's probably the demo's injected input stalling for more than 300 ms in the slow Simulator, but check it on a device.

## M4 Multi-finger: built and checked with synthetic input; the device check (stop point) is still due

Built:
- **Sessions:** fingers that land together, or that join resting or holding fingers, form a session of up to five. Session fingers never draw single-finger ink, and every single-finger gesture yields to them (R2). A finger that is already drawing keeps drawing.
- **Taps, progressively (R1):**
  - G16: two fingers ripple and pulse a filament between them.
  - G22: a third finger upgrades to a three-finger tap, with linked ripples in a triangle.
  - G23: four or five fingers make the palm splash: canvas flash, big burst, shockwave and a screen ripple.
- **Continuous gestures:** the session locks once a finger moves 12 pt, by whichever motion dominates.
  - G17: two-finger drag lays down a ribbon (ink, with a translucent fill and bright edges).
  - G18 pinch in: pulls ink in, then implodes with a flash. G19 pinch out: shockwave plus a water ripple through the ink.
  - G20 rotate: twists the ink, with orbiting particles.
  - G21 orbit: the held finger is a glowing core. The circling finger leaves a trail that becomes a ring, and particles keep orbiting afterwards.
  - G26 rake: one ink line per finger, with shimmer between them, committed as one undo step.
  - G22 swipe: a quick, fast three-finger rake turns into a wave sweeping across the canvas. The lines it consumed come back with one undo.
- **G25 drumming:** 4 or more quick taps in 1 s, alternating between spots. Ripples hop between the spots, linked by lightning. It beats G4 rhythm (R2). Multi-finger taps don't count as drum hits.
- **G24 gather and spread (stretch goal, D5):**
  - Five fingers closing pull all ink into one orb, and the canvas clears (one undo).
  - Five fingers opening make a nova and restore the ink exactly.
- **Ink distortion shader:** ripple, twist, pull and wave displace ink vertices, then let them return to rest. It's used by G18 to G20, G22 and G23, and now also G11's vortex and G14's magnet (closing two M3 gaps).
- **R8 (system gestures):** the canvas opts out of iPadOS three-finger editing gestures (undo/redo swipe, copy/paste pinch) with `editingInteractionConfiguration = .none`.
- **Main thread never waits on the GPU:** if three frames are still in flight, the renderer skips a frame instead of blocking the thread touches arrive on.

Ran:
- **Unit tests:** 116 pass. Every multi-finger gesture has positive and near-miss traces, for example:
  - a tap held too long, or with a finger sliding
  - three fingers not splashing
  - a one-sided pinch versus an orbit
  - a quick rake with four fingers staying a rake
  - a small gather cancelled
  - drumming on the same spot, too slowly, or with multi-finger taps

  There are also mapper tests (tap versus swipe effects, orbit core at the held finger, spread replacing the gathered orb).
- **Simulator** (iPhone 17 Pro), scripted multi-touch demo (`-demo4`): every gesture from G16 to G26 fired in order with plausible values, confirmed in the debug gesture log. Screenshots checked: ribbon, shockwave, orbit ring, rake, swipe wave with the lines consumed, drumming lightning, and gather clearing then spread restoring the ink.

**Not verified (this is the M4 stop point):**
- **Real fingers on real hardware:** the Simulator only fakes two touches, so all 3+ finger results come from injected events.
- **Thresholds:** the lock distance, swipe speed and gather progress are guesses.
- **Haptics:** the pulse once per orbit revolution, and every other haptic, waits for the haptics layer in M6.

**R8 conflicts expected on a real iPad, untested:**
- **G22:** the three-finger opt-out is in place, but whether iPadOS honors it everywhere is unknown.
- **G23 and G24:** four- and five-finger swipes and pinches are iPadOS multitasking gestures (Settings → Multitasking & Gestures). An app can't turn them off. The five-finger pinch will likely swallow G24's gather, which is D5's reason to cut it. Decide after trying it on an iPad.
- **G30:** screen-edge deferral needs a UIKit view-controller host. Planned for M5 along with G30.

Decisions and deviations (please check):
- **One shared recognizer for G16–G24 and G26:** they all depend on the same session membership and lock, so they share one session recognizer instead of one recognizer each. G25 is separate.
- **Rake versus swipe:** both are "three fingers moving together". A three-finger drag starts as a rake. It becomes a swipe if all fingers lift within 350 ms at 600 pt/s or more.
- **Erasing a ribbon:** a scribble that touches a ribbon removes the whole ribbon rather than splitting it.
- **Rotation momentum:** G20's "keeps spinning with momentum after release" is approximated. The twist eases out over 1 s and the orbiting particles keep circling for up to 3 s.
- **Demo playback:** the debug demos now feed their events from the frame loop with scheduled timestamps. Injecting in real time let Simulator main-thread stalls squash taps together, which produced fake holds and missed the swipe.

## M5 Contextual: done in unit tests and the Simulator, not yet on a device

Built:
- **Ink hit-testing:** the engine asks a small `InkHitTesting` protocol whether a point lands on ink, or a segment crosses it. The canvas answers from the ink model, with per-stroke bounds cached and rebuilt whenever the undo history's version changes.
- **G27 touch a stroke:**
  - A tap on ink begins on touch-down (R1) and outranks the tap family (R2).
  - The stroke vibrates like a plucked string, decaying, while two glows run from the touch point toward both ends. A longer stroke rings longer.
  - Dragging off the stroke cancels it and draws normally.
- **G28 cross a stroke:** a stroke being drawn fires at each crossing with existing ink. Sparks fly along both strokes and a small ripple runs through the ink.
- **G29 close a shape:** a stroke that ends on its own start, isn't circle-like, and encloses enough area is filled with translucent ink (ear-clipped, one undo with its outline). A glow floods out from the closing point and a faint pulse marks the center. Circles now need to be corner-free, so a square is G29, not G10.
- **G30 edge touch:**
  - A touch within 20 pt of an edge makes a glowing bumper along that edge, with a short wave pushing inward and nudging ink.
  - The touch can still draw afterwards.
- **G32 idle:**
  - After 5 s with no touch, motes drift slowly and the ink shimmers. Everything dims to 35% after about 30 s.
  - The frame rate drops to 30 Hz. Any touch restores 120 Hz from touchesBegan itself, before the next frame.
- **R8:** the app now runs on a UIKit scene whose root view controller defers all screen-edge system gestures and hides the home indicator. SwiftUI chrome for M7 will sit on top as a child.

Ran:
- **Unit tests:** 139 pass. Positive and near-miss traces for each gesture, using a mock ink canvas:
  - G27: tap beside the ink; drag off the stroke draws instead
  - G28: stroke stopping short; no ink
  - G29: open shape; circle stays G10; square no longer counts as a circle
  - G30: touch away from the edge
  - G32: a 4 s pause; a finger resting for 7 s

  Ink query tests cover hit, crossing, the bounds index, concave fill area, and fill dropped on erase.
- **Simulator** (iPhone 17 Pro), scripted demo (`-demo5`):
  - G27, G28, G29, G30 (left and bottom edges) and G32 fired in order, confirmed in the gesture log.
  - Idle began exactly 5 s after the last touch and ended on the next tap.
  - Screenshots: plucked line, crossing, filled square with flood glow, idle at 30 Hz, dimmed after 30 s, restored on touch.

**Not verified:** real fingers and real devices. The R8 edge deferral needs a real device to tell whether the first edge swipe reaches G30; iPadOS Slide Over and Stage Manager edges may still win. Not measured: the worst-case delay after idle at 30 Hz before a touch shows up (at most about one 30 Hz frame, 33 ms), and battery use while idle (M8).

Decisions and deviations (please check):
- **G27 wobble:** the stroke's vibration is a glowing overlay drawn along the stroke, not the ink itself bending.
- **G29 flood:** the fill appears at full strength at lift. The "flood spreads fast" is a bloom from the closing point, not a reveal clipped to the shape.
- **G30:** fires on touch-down only. A swipe that starts at the edge gets the same response, plus whatever the stroke does.
- **G31 after edge touches:** an edge touch claims its lift, so it doesn't also bloom a G31 halo.
- **Self-intersecting shapes:** a figure-eight fills with a fan from its center, which can look wrong.

## M6 Haptics: built and unit-tested; feeling and tuning on a real iPhone is still due (stop point)

**Haptics have not been felt.** Core Haptics doesn't run in the Simulator, so on this Mac the haptics code was only compiled and unit-tested. Nothing in this section was felt on a device.

Built:
- **Palette as data (Appendix B):** Tick, Thud, Snap, Soft rumble, Swell, Pulse, Texture, Burst, Crackle and Settle are recipes in `BaseResponseSet.json`, generated by `Engine/Tools/make_base_response_set.py`.
  - Starting values are copied from the spec, for example Tick is intensity 0.4 and sharpness 0.7.
  - Swell rises from 0.1 to 0.8 and Settle falls to 0 over 0.4 s, through intensity curves.
  - Pulse is two transients 120 ms apart. Burst is 6 transients with spacing growing and intensity falling. Crackle is fixed pseudo-random transients over about 0.9 s.
- **Per-gesture cues as data:** each gesture lists what plays and when (start, release or edge bounce), with optional delay, strength, condition, and the live input that drives a held haptic. For example:
  - G7 Texture follows finger speed (intensity and sharpness)
  - G5 Swell follows hold time
  - G13 swells while stretching and snaps on release
  - G4 Pulse loops at the tapped tempo for 8 s
  - G21 pulses once per revolution
  - G8 ticks on every comet bounce
  - G11 swells inward, settles outward
  - G22 bursts for a tap, a short Texture for a swipe
  - G2 adds only the Thud, because G1 already ticks underneath it (R1 layering)
- **Mapper:**
  - Held haptics (Texture, Swell, Soft rumble) start on `began`, update from live input on `changed`, and stop the moment the gesture ends or is cancelled.
  - Everything else plays once.
  - With no haptics hardware, the mapper sends nothing and visuals get the 1.2× boost instead (R5).
- **App player (`HapticsPlayer`):**
  - Created only if `supportsHaptics` is true at runtime.
  - Engine started at launch with auto-shutdown off, and restarted from its stopped and reset handlers.
  - Each recipe is built once into a pool of 4 reusable players.
  - All Core Haptics calls go to a private serial queue, off the frame loop.
- Fixed a launch error: the scene manifest is now declared only in Info.plist.

Ran:
- **Unit tests:** 151 pass, including 12 new haptic mapping tests:
  - every palette entry has in-range values
  - held Texture follows speed and stops on lift
  - a cancelled hold stops its Swell
  - the slingshot snaps on release
  - Pulse loops at the tapped tempo
  - the orbit pulses once per revolution
  - the spiral and G22 pick their haptics
  - the comet bounce ticks
  - every gesture except idle has a cue
  - no-haptics hardware gets none
- **Simulator** (no haptics hardware, so this is the iPad path): iPhone and iPad simulators ran the gesture demos with no haptic or scene errors.
- **Device build:** compiles and signs.

**Not verified:**
- **Feel:** how anything feels, including whether held haptics stop crisply, whether looping Pulse and rapid Ticks overlap well, and whether the starting recipes are too strong or weak.
- **Battery:** the cost of keeping the engine running (M8).
- **iPad without errors on a real device:** the same no-haptics path as the Simulator, but not yet run on hardware.

**Tuning:** change values in `make_base_response_set.py` (the `PALETTE` and `HAPTICS` tables), run it, and rebuild. No logic changes are needed.

## Known issues and deviations

- **Metal Toolchain not installed.** Shaders are compiled at launch from `ShaderSource.swift` (`makeLibrary(source:)`), which adds a few ms during warm-up and nothing on the touch path. To precompile instead, install the toolchain with `xcodebuild -downloadComponent MetalToolchain` (about 700 MB) and move the source back to a `.metal` file.
- Particle slots are rewritten in place, so a slot reused while a frame is in flight can draw one particle wrong for one frame. Not visible in testing.
- The effect system and frame loop run on the main thread. Revisit if device profiling shows dropped frames.
- Rendering runs on the main thread for now. Revisit after the device numbers if frames are missed.
- Screen-edge deferral (R8) needs a UIKit view controller host. Planned for M4/M5.
